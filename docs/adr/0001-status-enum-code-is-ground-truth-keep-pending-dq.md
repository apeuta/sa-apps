# Enum `Projects.status` mengikuti kode, `Pending DQ` dipertahankan

Spec awal mendefinisikan `New, Assigned, Pending DQ, Ready, Closed-Win, Lost`, sedangkan kode punya status operasional tambahan (`Pending Assignment, Handover Complete, Need Clarification, Scoring Pending, Manual Review Required`) dan menghilangkan `Pending DQ`. Kami memutuskan status operasional kode menjadi ground truth baru (spec dikoreksi) karena mereka nyata dan dipakai oleh flow AI scoring + handover yang sudah berjalan — bukan penyimpangan niat, melainkan detail yang spec awal tidak antisipasi. Namun `Pending DQ` dikembalikan: ia milik Flow 2 (SLA DQ gating) yang sedang dihidupkan di Fase 2A dan hilang karena kelalaian kode, bukan keputusan. Mengubah enum status sulit dibalik (menyentuh CheckConstraint DB + migration + state machine), sehingga keputusan ini dicatat agar enum yang "aneh" tidak di-"rapikan" kembali ke spec lama.
