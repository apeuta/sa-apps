# SLA Flow 2 dijalankan scheduler internal ringan (MVP)

Flow 2 butuh aksi berbasis waktu (reminder H+3, eskalasi H+5, auto-lock folder Solutions) via `process_sla_actions()`. Kami memilih background scheduler internal ringan yang jalan saat startup backend, bukan cron eksternal yang memanggil `POST /sla/process`. Alasan: satu proses, tanpa dependency infra tambahan, lebih mudah di-deploy dan diverifikasi end-to-end untuk MVP single-instance. Konsekuensi yang perlu disadari: pilihan ini **tidak aman saat backend di-scale multi-instance** (setiap instance akan menjalankan scheduler dan menduplikasi aksi SLA). Saat scale-out, pindah ke cron eksternal atau tambahkan leader-election. Dicatat sebagai ADR karena batas "aman untuk MVP, tidak untuk multi-instance" tidak terlihat dari kode scheduler itu sendiri.
